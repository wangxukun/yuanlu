# P1-a 实施方案：metadata 全家桶 + JSON-LD 扩充

## 背景与架构决策

**现状**：项目无 `app/layout.tsx` 根布局，`(main)/layout.tsx` 和 `admin/layout.tsx` 各自独立渲染 `<html>/<body>`（路由组各自带根布局模式）。全局 metadata 极简陋（仅 title/description），完全缺失 metadataBase、canonical、twitter、og:image、icons。JSON-LD 仅 episode 页一处，且硬编码域名。

**核心架构决策**：在 `(main)/layout.tsx` 的 `metadata` export 中扩展站点级配置（而非新建 `app/layout.tsx`）。理由：

- `(main)/layout.tsx` 的 metadata 会自动继承给所有面向用户的公开页（episode/podcast/channel/discover/home），一次配置全局生效。
- admin 是独立分支且已 `robots: noindex`，不受影响也不需要这些 SEO 配置。
- 零重构风险（不动 `<html>/<body>` 结构）。

## 改动清单

### 1. 扩展 `lib/site.ts`（集中品牌常量）

在现有 `SITE_BASE_URL` 基础上，新增站点名、默认 OG 图、twitter 账号等常量，消除散落各处的硬编码品牌字面量：

```ts
export const SITE_BASE_URL = ...;
export const SITE_NAME = "远路播客";
export const SITE_NAME_EN = "Yuanlu Podcast";
export const SITE_DESCRIPTION = "...英语听力学习...";
export const DEFAULT_OG_IMAGE = "/static/images/apple-touch-icon-light.png";
```

### 2. 扩展 `app/(main)/layout.tsx` 的 metadata（站点级配置）

把当前简陋的 metadata 扩展为完整的站点级配置，所有子页面继承：

- `metadataBase: new URL(SITE_BASE_URL)`（**必须**，让所有相对路径的 OG 图/canonical 正确解析）
- `title: { default: SITE_NAME, template: "%s | 远路播客" }`（子页面只需设 title，自动带后缀）
- `description`、`applicationName`、`keywords`（英语听力、双语逐字稿等核心词）
- `openGraph`：默认 `type: "website"`、`locale: "zh_CN"`、`siteName`、`url`、`images: [DEFAULT_OG_IMAGE]`
- `twitter: { card: "summary", title, description, images: [DEFAULT_OG_IMAGE] }`
- `icons`：引用 `favicon.ico` + `favicon-16x16.png` + `favicon-32x32.png`（让现有 png 生效，当前未被自动注入）
- `alternates.canonical: SITE_BASE_URL`（首页规范）
- `robots: { index: true, follow: true }`

> 注：`(main)/layout.tsx` 当前是静态 `metadata` 对象，保持静态即可（站点级配置无需动态生成）。

### 3. 新建 `components/seo/JsonLd.tsx`（可复用 JSON-LD 组件）

一个纯服务端组件，封装 `<script type="application/ld+json">`：

```tsx
export default function JsonLd({ data }: { data: Record<string, unknown> }) {
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(data) }}
    />
  );
}
```

各页面 import 后传入结构化数据对象，统一注入方式。

### 4. 新建 `components/seo/Breadcrumbs.tsx`（可视化面包屑 + JSON-LD 二合一）

服务端组件，渲染**可视化面包屑导航**（用户可见 + 符合现有 DaisyUI/Tailwind 风格），**同时输出 `BreadcrumbList` JSON-LD**。Props 接收 `items: {name, url}[]`，最后一项为当前页（不可点击）。这样既改善用户体验又满足结构化数据要求，一举两得。

### 5. 改造各公开页（加 canonical + JSON-LD + 面包屑）

#### 5a. `app/(main)/episode/[id]/page.tsx`

- **generateMetadata** 增加 `alternates.canonical: \`${SITE_BASE_URL}/episode/${id}\``
- **OG/Twitter**：当前已有 openGraph，补充缺失字段（locale、siteName、url），由站点级继承覆盖大部分
- **JSON-LD**：用 `<JsonLd>` 组件替换现有内联 `<script>`；修复硬编码域名（第 92 行 `https://www.wxkzd.com` → `SITE_BASE_URL`）；补充 `BreadcrumbList`（首页 > 频道 > 播客 > 单集）
- **面包屑**：页面顶部渲染 `<Breadcrumbs>`
- 顺带把 episode 页的 JSON-LD 从 `PodcastEpisode` 扩展，加 `inLanguage: "en"`、`author`

#### 5b. `app/(main)/podcast/[id]/page.tsx`

- **generateMetadata** 增加 `alternates.canonical`
- **新增 JSON-LD**：`PodcastSeries`（name/description/image/url/author）+ `BreadcrumbList`（首页 > 频道 > 播客）
- **面包屑**：渲染 `<Breadcrumbs>`

#### 5c. `app/(main)/channel/[name]/page.tsx`

- **generateMetadata** 增加 `alternates.canonical`
- **新增 JSON-LD**：`CollectionPage` 或 `ItemList`（聚合该频道下的播客）+ `BreadcrumbList`（首页 > 频道）
- **面包屑**：渲染 `<Breadcrumbs>`（注意 channel 页当前是 ChannelClient 客户端组件，面包屑需在 server page 层渲染，传给 client 或在 server page 外层包）

#### 5d. `app/(main)/discover/page.tsx`

- **metadata** 增加 `alternates.canonical: \`${SITE_BASE_URL}/discover\``
- **新增 JSON-LD**：`WebSite` + `SearchAction`（启用 Google sitelinks 搜索框；需要站点有搜索功能，项目已有 `/search` 路由）+ `Organization`（站点主体信息）

> discover 页作为站点门面，放 `WebSite` + `Organization` 是最合适的位置（比塞进 layout 更语义化）。

### 6. 修复 episode 页 JSON-LD 硬编码域名

`episode/[id]/page.tsx` 第 92 行 `https://www.wxkzd.com/podcast/...` → 用 `SITE_BASE_URL` 拼接。这是 P0 时遗留的。

## 不做的事（明确边界）

- ❌ 不新建 `app/layout.tsx`（重构风险高，用 `(main)/layout.tsx` 站点级 metadata 替代）。
- ❌ 不处理根 `/` 空洞页内容（那是独立的内容策略问题，留后续）。
- ❌ 不配置 Google/百度站长验证 meta（用户选择暂不处理）。
- ❌ 不做 URL slug、ISR、301（P1-b / P2 范畴）。
- ❌ 不把 channel/series/trending 加进 sitemap（范围控制，后续可做）。
- ❌ 不动 admin（已 noindex，独立分支）。

## 验证方式

1. `npx tsc --noEmit` 无错误。
2. `npx eslint <改动文件>` 无错误。
3. dev server 实跑：
   - episode 页：`<link rel="canonical">` 存在；JSON-LD 含 PodcastEpisode + BreadcrumbList；面包屑可见；OG 图指向默认 logo（无封面时）。
   - podcast 页：JSON-LD 含 PodcastSeries + BreadcrumbList；canonical 存在。
   - channel 页：JSON-LD 含 ItemList + BreadcrumbList；canonical 存在。
   - discover 页：JSON-LD 含 WebSite + Organization + SearchAction；canonical 存在。
   - 任意页 `<head>`：含 `metadataBase` 解析后的绝对 OG URL、twitter:card、favicon 链接。
4. 用 Google 富媒体测试思路抽查：每类 JSON-LD 语法正确（无重复 @context）。

## 影响面

- 新增 2 个组件（JsonLd、Breadcrumbs）。
- 扩展 1 个常量文件（lib/site.ts）。
- 修改 5 个页面文件 + 1 个 layout。
- 全部为 SSR metadata / JSON-LD 增强，不改变现有页面交互逻辑。
- 风险极低：metadata 是声明式的，JSON-LD 与面包屑是纯增量 DOM。
