# 修复原声播放首次 20s+ 延迟

## 根因（已确认）

`useSpeechEvaluation.ts` 的 `ensureAudioBuffer()`(行 643-653)首次播放时**串行下载整个剧集音频**(20-60MB)→ `arrayBuffer()` → `decodeAudioData()`,这是 20s+ 延迟的来源。第二次点击快是因为 `AudioBuffer` 缓存在 `audioBufferCacheRef`(per-hook 实例)。

两个加剧因素:

1. 缓存是**每 hook 实例独立**的——每个 `SpeechEvaluationCard` 各下一遍同一集音频(同一 episodeId、同一文件)。
2. **没有任何预加载**——用户点击前啥也不做。

`decodeAudioData` 无法流式解码(需完整文件),所以只能靠**空闲预加载 + 跨卡片共享剧集缓存**。

## 修复方案(两步)

### 1. 把 AudioBuffer 缓存从 hook 实例提升为**模块级剧集缓存**

在 `useSpeechEvaluation.ts` 文件顶层新增模块级 Map:

```ts
// 模块级：同一集的 AudioBuffer 跨所有 SpeechEvaluationCard 共享，只下载+解码一次
const episodeBufferCache = new Map<
  string,
  { buffer: AudioBuffer; promise: Promise<AudioBuffer> | null }
>();
```

改写 `ensureAudioBuffer` 去查这个 Map(以 `fetchUrl` 为 key):

- 命中已解码 buffer → 立即返回(同卡片第二次、不同卡片第一次都秒开)。
- 命中进行中的 promise → 复用(避免并发重复下载)。
- 未命中 → 创建 promise,fetch+decode,成功后存入 Map。

保留卸载时的清理逻辑,但**只清理 AudioContext**,不清模块缓存(让同集 buffer 跨卡片存活,真正用完再靠页面切换自然失效;Map 体量小,不构成内存问题——一集一个 AudioBuffer)。

### 2. hook 挂载时**后台预加载**当前集的 AudioBuffer

在 `useSpeechEvaluation` 末尾加一个 effect:

```ts
useEffect(() => {
  // 空闲时间后台预取整集音频,首次点击原声时大概率已就绪
  const fetchUrl = episodeId
    ? `/api/episode/audio-proxy?id=${encodeURIComponent(episodeId)}`
    : audioUrl;
  if (!fetchUrl) return;
  // 复用 ensureAudioBuffer 同款逻辑(已含去重),fire-and-forget
  // 用 requestIdleCallback 避免抢占首屏渲染;不支持则 setTimeout(1500)
  ...
}, [episodeId, audioUrl]);
```

- **不阻塞 UI**:用 `requestIdleCallback`(降级 `setTimeout`),让首屏渲染/交互优先。
- **失败静默**:预加载失败不报错,真正点击时 `playReferenceAudio` 会重试并 toast。
- 预加载与点击共用同一个 Map entry → 点击时若已完成则秒开,若未完成则等待同一 promise(比现在快,因为已提前下了一部分)。

### 关键实现注意

- `ensureAudioBuffer` 内部逻辑基本不变,只是数据源从 3 个 ref(`audioBufferCacheRef`/`audioBufferUrlRef`/`audioBufferPromiseRef`)改为模块 Map。可保留 ref 作为兼容或直接删除(改为纯函数查 Map)。
- 预加载 effect 必须用 `ensureAudioBuffer` 同款去重,否则会重复下载。
- 浏览器 AudioContext 自动暂停策略:预加载只做 fetch+decode(不需 AudioContext 运行态);真正播放时 `startPlayback` 里已有 `ctx.resume()`,不受影响。

## 预期效果

| 场景                 | 修复前           | 修复后                                                   |
| -------------------- | ---------------- | -------------------------------------------------------- |
| 同卡片首次点原声     | 20s+             | 多数已预加载完→秒开;网络慢时等同一 promise(比串行从头快) |
| 同卡片第二次点       | 秒开             | 秒开(Map 命中)                                           |
| 不同卡片(同集)首次点 | 重新 20s+        | 秒开(模块 Map 命中)                                      |
| 不同集切换           | 该集首次仍需下载 | 切到新集后空闲预加载该集                                 |

## 验证

- `npx tsc --noEmit` 无新增错误。
- 实测:打开评测页等几秒,首次点原声秒开;切到同集下一句也秒开。
